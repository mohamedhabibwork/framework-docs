title: 'CLI reference'
description: 'Every command, option and example of the application CLI.'

Every application exposes the same CLI through its own `bin/cli.ts`. From an app
directory run `bun run cli -- <command>`; from the workspace root use
`bun run cli -- <command> --cwd apps/<app>`. The CLI never guesses the project
from the shell's working directory — the project root comes from the
application's own adapter.

```sh
bun run cli -- list                    # the live catalog
bun run cli -- make:crud --help        # usage, options, examples, requirements
```

## Shared options

| Option              | Effect                                                                                               |
| ------------------- | ---------------------------------------------------------------------------------------------------- |
| `--help`, `-h`      | Usage, arguments, options, examples, capability requirements                                         |
| `--version`, `-V`   | CLI and framework versions                                                                           |
| `--cwd <path>`      | Explicit project root                                                                                |
| `--env-file <path>` | Explicit environment file (process env still wins)                                                   |
| `--json`            | Machine-readable envelope on stdout: `{ command, status, data, warnings }`; diagnostics go to stderr |
| `--no-interaction`  | Disable prompts; missing required input is an error                                                  |
| `--verbose`         | Additional diagnostics (secrets redacted)                                                            |

Exit codes: `0` success · `1` execution failure · `2` invalid usage ·
`3` unsupported capability · `130` interrupted.

`--json` is the contract for scripts and agents: `status` is `ok` or `error`,
`data` is command-specific, `warnings` never fail a run. Human formatting stays
on the text path.

## Project

### `create <directory>`

Generate a complete application into an empty directory.

| Option                                         | Effect                                                                                          |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `--with-demo`                                  | Also generate a sample `products` module (files + migration) via `make:crud` inside the new app |
| `--no-install`                                 | Skip dependency installation (also skips `--with-demo`)                                         |
| `--template`, `--runtime`, `--package-manager` | Only `api` / `bun` / `bun` are validated                                                        |

```sh
bun run cli -- create apps/inventory-api --with-demo
```

Generated apps are workspace members: `@framework/*` resolves through the
framework workspace after a root `bun install` (run automatically unless
`--no-install`).

### `help [command]`, `list [--json]`

Command help and the full catalog, including planned commands.

### `config:check`, `config:show [key]`

Validate configuration without starting anything; show resolved configuration
with secrets redacted.

```sh
bun run cli -- config:show database.url
```

### `doctor [--connections]`

Configuration validation plus optional database connectivity probe.

### `route:list [--method <m>] [--path <fragment>] [--json]`

The registered route table (method, path, handler count). Boots binding
registration only — no connections are opened.

### `module:list`, `middleware:list`

Registered providers, middleware aliases and groups.

### `serve [--host] [--port]`, `dev [--host] [--port]`

Production server; `dev` adds the Bun hot-reload watcher. Both delegate to the
app's entry points and forward interrupts.

## Generators

### `make:crud <Resource>`

The one-command CRUD feature. Generates the Drizzle table (new resources),
Drizzle–Zod schemas, DTOs, form requests, repository (mixins), service,
controller, policy, typed native Hono routes, OpenAPI operations, fixtures and
an endpoint test suite — then registers everything through explicit markers.

| Option                            | Effect                                                                                                                    |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `--module <name>`                 | Destination module (default: resource plural)                                                                             |
| `--fields '<spec>'`               | New table: `name:type:required\|nullable\|default=<literal>, …` (types: text, integer, numeric, boolean, uuid, timestamp) |
| `--table <export>`                | Reuse an existing Drizzle table export (mutually exclusive with `--fields`)                                               |
| `--schema-file <path>`            | Where `--table` is exported (default: schema index)                                                                       |
| `--definition <path>`             | JSON resource definition for enums/relations/exposure/fixtures                                                            |
| `--route <path>`                  | Mount path (default `/api/v1/<module>`)                                                                                   |
| `--access public\|authenticated`  | `public` mounts without auth; `authenticated` requires `make:auth` and maps CRUD abilities to token abilities             |
| `--soft-delete`                   | Adds `deletedAt`, restore behavior and deletion tests                                                                     |
| `--verify`                        | Typecheck + run the endpoint suite on an isolated PostgreSQL database                                                     |
| `--test-mode in-process\|network` | Endpoint transport for verification (default in-process)                                                                  |
| `--dry-run`                       | Preview every file change and the test plan; write nothing                                                                |
| `--force`                         | Overwrite generator-owned files of this module only                                                                       |

```sh
bun run cli -- make:crud Category \
  --fields 'title:text:required,position:integer:default=0,budget:numeric:nullable' \
  --access public --soft-delete --verify
```

Every endpoint is tested against a real database (never a mock): create → list →
read → update → read → delete → missing-read, plus malformed input, forbidden
fields, allowlist exposure and pagination bounds. `make:crud` refuses to invent
columns, overwrite unrelated files, or collide routes.

### `make:auth`

Install session + personal API token authentication into an application: the
`app/modules/auth` module (provider + routes), the `@framework/auth` dependency,
config section, schema exports, kernel `resolveActor` guard, the `/api/v1/auth`
mount and the auth-tables migration.

| Option            | Effect                                                        |
| ----------------- | ------------------------------------------------------------- |
| `--guards <list>` | Enabled guards, comma separated (default `session,api-token`) |
| `--dry-run`       | Preview every change and the migration plan; write nothing    |
| `--force`         | Overwrite generator-owned files of the auth module            |

Refuses to run when auth is already installed. The migration is generated, not
applied — `db:migrate` stays an explicit release step.

### `make:module <name> --crud <Resource>`

Module routes/provider/exports with an explicit module name; `--crud` delegates
to the same `make:crud` pipeline.

### Single-artifact generators

`make:schema`, `make:repository`, `make:dto`, `make:request`, `make:response`,
`make:service`, `make:controller`, `make:policy`.

One artifact of the `make:crud` pipeline at a time, rendered by the same code so
output is byte-identical to a whole-module generation. Table-coupled slices
introspect an existing Drizzle export (`--table`, default: the resource's
plural) and refuse with actionable hints when a sibling artifact they import is
missing — `make:schema` starts a table-first module, `make:crud` remains the
whole-module path.

### Runtime scaffolds

`make:middleware`, `make:provider`, `make:event`, `make:listener`, `make:test`.

Standalone, typecheckable scaffolds registered through the app's markers:
`make:middleware` aliases into `bootstrap/middleware.ts` (`@framework:middleware`),
`make:provider` into `bootstrap/providers.ts`, `make:listener` into the
`app/listeners` registry (`@framework:listeners`, subscribed by the listeners
provider at boot). `make:test --api` scaffolds an endpoint test through the
generated `tests/support.ts`.

### Application scaffolds

All share the `make:crud` pipeline (`--dry-run` writes nothing, existing files
are conflicts unless `--force`, registries update through `// @framework:*`
markers) and refuse up front when the generated code would import a package the
app does not depend on.

| Command                                                                     | Writes                                                | Notes                                                                                                                                                     |
| --------------------------------------------------------------------------- | ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `make:mail <name>`                                                          | `app/mail/<name>.mail.ts`                             | Typed data → subject/text/HTML (interpolations HTML-escaped) and a `send<Name>Mail(mailer, to, data)` helper. Needs `@framework/mail`                     |
| `make:notification <name> [--channels email,database,push,messaging]`       | `app/notifications/<name>.notification.ts`            | `defineNotification` with one builder per declared channel (default `email,database`). Needs `@framework/notifications`                                   |
| `make:command <name> [--signature group:name]`                              | `app/commands/<name>.command.ts`                      | Registered in `app/commands/index.ts` and appended to the catalog in `bin/cli.ts` (default signature `app:<name>`; existing names refused)                |
| `make:schedule <name> (--job <job> \| --workflow <name>) [--cron "<expr>"]` | `app/schedules/<name>.schedule.ts`                    | Registered under `@framework:schedules`; `--job` must exist (`make:job`); cron is validated as five fields (default hourly). Needs `@framework/scheduler` |
| `make:job <name>`                                                           | `app/jobs/<name>.job.ts`                              | Versioned, validated payload plus handler, registered in the jobs list                                                                                    |
| `make:seeder <name>`, `make:factory <name>`                                 | `database/seeders/…`, `database/factories/…`          | Registered in the seeder/factory lists; consumed by `db:seed` and by tests                                                                                |
| `make:guard <name> [--header x-api-key]`                                    | `app/auth/guards/<name>.guard.ts`                     | `ActorResolver` reading one credential header; compose it in the kernel's `resolveActor`                                                                  |
| `make:user-provider <name>`                                                 | `app/auth/<name>.user-provider.ts`                    | `UserProvider` decorating `DatabaseUserProvider`; bind as `USER_PROVIDER`. Needs `@framework/auth`                                                        |
| `make:migration <name>`                                                     | `database/migrations/NNNN_<name>.sql` + journal entry | Empty custom SQL migration via the pinned `drizzle-kit generate --custom`                                                                                 |

## Database

| Command                            | Effect                                                                                                |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `db:generate --name <name>`        | Diff the schema with pinned Drizzle Kit (offline); review the SQL afterwards                          |
| `db:migrate [--connection <name>]` | Apply pending migrations under an advisory lock                                                       |
| `db:status [--json]`               | Applied/pending migration state                                                                       |
| `db:check`                         | Validate migration metadata (`drizzle-kit check`)                                                     |
| `db:seed [seeder]`                 | Run every registered seeder, or one by name                                                           |
| `db:fresh [--force]`               | Drop the public schema and re-run the journal (destructive; `--force` overrides the production guard) |

Migrations are never applied automatically on startup — applying them is an
explicit release step.

## Queues

| Command                                           | Effect                                                                |
| ------------------------------------------------- | --------------------------------------------------------------------- |
| `queue:work [--queue <name>] [--concurrency <n>]` | Consume the queue in the foreground; SIGTERM/SIGINT drains gracefully |
| `queue:status [--queue <name>] [--json]`          | Job counts per state (waiting/active/completed/failed/delayed)        |
| `queue:failed [--queue <name>]`                   | Failed-job records: id, name, attempts, reason                        |
| `queue:retry <id>`                                | Re-queue one failed job (payload and idempotency key unchanged)       |
| `queue:retry-all [--limit <n>]`                   | Re-queue failed jobs oldest-first (default 100)                       |
| `queue:forget <id>`                               | Delete one failed-job record without retrying                         |
| `queue:prune [--hours <n>]`                       | Remove terminal records older than the threshold (default 168)        |
| `queue:pause`, `queue:resume`                     | Pause consumption (in-flight jobs finish), then resume                |

All require a reachable Redis (`config redis.url`).

## Search

| Command                            | Effect                                                              |
| ---------------------------------- | ------------------------------------------------------------------- |
| `search:status`                    | Driver, capabilities and declared indexes                           |
| `search:index [index] [--dry-run]` | Import declared indexes from their source tables (all when omitted) |
| `search:flush <index> [--dry-run]` | Truncate one declared index                                         |

Requires `search.driver: postgres`; the `memory` driver lives inside one process,
so CLI indexing refuses it with exit `3` instead of silently doing nothing.

## Cache and maintenance

| Command                                    | Effect                                                                   |
| ------------------------------------------ | ------------------------------------------------------------------------ |
| `cache:clear [--store <name>] [--confirm]` | Clear the cache namespace (`--dry-run` previews; `--confirm` required)   |
| `session:prune [--confirm]`                | Remove expired sessions (`--dry-run` only counts them)                   |
| `storage:check`                            | Validate disk configuration read-only; roots are reported, never created |

Each requires the matching provider to be registered in
`bootstrap/providers.ts`; without it the command exits `3` with an actionable
hint.

## Tooling and build

`typecheck`, `test [--filter]`, `lint [--fix]`, `format [--check]` delegate to
the project-configured executables (`tsc`, `bun test`, `oxlint`, `oxfmt`). The
CLI never re-implements compilers or formatters.

`build [--target server|worker|scheduler]` compiles standalone binaries with
`bun build --compile --minify --sourcemap` into `dist/` (every entry point that
exists by default; optional peer SDKs stay external).

## Planned commands

The remaining specification catalog is listed by `list` with status `planned`
and exits with code `3` when invoked:

| Command                                                          | Why it is not shipped yet                                                                                   |
| ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `make:model`, `make:integration`, `integration:*`                | The ORM layer is out of scope; adapters are not a supported surface                                         |
| `db:rollback`                                                    | Migrations are forward-only by decision — use `db:fresh` (non-production) or author a new forward migration |
| `cache:prune`, `storage:link`, `storage:prune`                   | Adapter-specific cleanup that no shipped driver needs yet                                                   |
| `oauth:client:create`, `oauth:client:list`, `oauth:key:generate` | Client registration and key generation are code/API-level today ([OAuth server](/oauth-server/))            |
| `observatory:*`                                                  | The package ships contracts only ([Packages](/packages/))                                                   |
| `socialite:providers`                                            | The package ships contracts only ([Packages](/packages/))                                                   |

See [Implementation status](/status/) for the evidence behind each delivered
command.
