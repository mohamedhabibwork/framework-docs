<section aria-labelledby="features-title">
  <div class="section-head">
    <div>
      <span class="section-kicker">What ships</span>
      <h2 id="features-title">Batteries included, defaults that run</h2>
    </div>
    <p>
      Every subsystem is wired, tested against real infrastructure and documented — no starter-kit archaeology required.
    </p>
  </div>
  <div class="features">
    <Feature icon="bolt" title="One-command applications">
      <code>create --with-demo</code> scaffolds config, providers, health/audit/realtime routes, server, worker and CLI
      entry points, a test suite and a sample module — then installs and migrates.
    </Feature>
    <Feature icon="table" title="CRUD from one table">
      <code>make:crud</code> derives Drizzle–Zod schemas, DTOs, repository, service, controller, typed routes, OpenAPI
      metadata and an endpoint suite, then verifies them on PostgreSQL.
    </Feature>
    <Feature icon="shield" title="Audited by default">
      Every write lands in <code>audit_logs</code> inside the same transaction, with field-level diffs, actor and
      correlation id — queryable over HTTP.
    </Feature>
    <Feature icon="flow" title="Queues, schedules, workflows">
      BullMQ jobs with validated payloads and idempotency keys, cron schedules with distributed locks, and durable
      workflows with saga compensation.
    </Feature>
    <Feature icon="key" title="Authentication that ships">
      Sessions and personal API tokens, email verification, password recovery, TOTP two-step login, JWT/JWKS guards and
      token abilities.
    </Feature>
    <Feature icon="schema" title="OpenAPI that cannot drift">
      Operations derive from route metadata and Zod; <code>openapi:check</code> fails when the document and the live
      route table disagree.
    </Feature>
  </div>
</section>

      <h2 id="paths-title">Start from the template, or inside the workspace</h2>

    <p>Both paths end in the same running API; pick the one that matches how you will ship.</p>
  </div>
  <div class="paths">
    <article class="path">
      <span class="path-step">Path A — standalone</span>
      <h3>Clone the template repository</h3>
      <p>
        A standalone application with its own git history, Dockerfile and compose file. Framework packages resolve from
        GitHub.
      </p>
      <pre>
        <code>
          <span class="prompt">$</span> gh repo create my-api --template mohamedhabibwork/framework-app --clone
          <span class="prompt">$</span> cd my-api &amp;&amp; bun install
          <span class="prompt">$</span> cp .env.example .env
          <span class="prompt">$</span> docker compose -f deployment/compose.yaml up -d --wait
          <span class="prompt">$</span> bun run cli -- db:migrate &amp;&amp; bun run dev
        </code>
      </pre>
