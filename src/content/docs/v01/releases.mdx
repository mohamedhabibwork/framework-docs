Each release is tagged `vX.Y.Z` in the repository and recorded in the root
`CHANGELOG.md` (Keep a Changelog format); this page is the narrative companion
— what a release means for the framework and its docs. Every pre-1.0 minor
release also freezes a docs snapshot of the previous line, as described on the
[Versions](/versions/) page.

## 0.1.0 — 2026-10-04

The first tagged release. Delivery phases 0–4 are complete: runtime and
adapter decisions, the core container and HTTP kernel, a coherent CRUD
platform, sessions and tokens, and the full set of infrastructure subsystems
backed by the `@mohamedhabibwork` kit adapters.

### Highlights

- **Core and HTTP** — container (singleton/scoped/transient, cycle detection),
  validated frozen config, graceful shutdown, execution context; HTTP kernel
  with request ids, error envelope, middleware registry, policies and auth
  plumbing.
- **Database and CRUD** — postgres-js connections, AsyncLocalStorage
  transactions with savepoints, CRUD mixins, audit trail written in the same
  transaction, migrations; a generic resource layer with audit routes,
  import/export and OpenAPI 3.1 generation with a route drift check.
- **Auth** — sessions, personal API tokens, guards and auth endpoints, plus
  login rate limiting built on the cache rate limiter.
- **Events and realtime** — typed event bus (in-memory or Redis pub/sub) and a
  channel-allowlisted WebSocket hub.
- **Queues, scheduling and workflows** — BullMQ dispatch/worker/batches, cron
  scheduling on job schedulers, and a durable workflow/pipeline/stage engine.
- **Kit-backed subsystems** — cache (CacheKit: memory/Redis, locks, fixed-window
  rate limiting), storage (StorageKit: local disk driver), mail
  (message/transport with redacted console transport), logging (LoggerKit
  sinks with ambient correlation and redaction) and notifications (explicit
  channels including push and messaging over NotifyKit).
- **Tooling** — the CLI's `create` and `make:crud` generators, infrastructure
  commands (`cache:clear`, `storage:check`, `session:prune`), Laravel-style
  helpers, an isolated test harness, and a reference playground application.
- **Docs** — the Starlight documentation site you are reading, with guides for
  every subsystem and Laravel-style versioned snapshots.

For the commit-level changelog, see `CHANGELOG.md` in the repository root.
