# Implementation Status

Release classification required by `framwork.md` §10. **Validated** means covered by an automated test that passes in `bun run test`; **implemented** means working and exercised manually but without a dedicated automated test; **planned** means specified but not built (the CLI lists it and exits with code 3).

Last verified: 2026-10-27 — `bun run test` all green (427 tests incl. the scaffold-generator gate, validation/testing package suites and deepened scheduler/events/ai-mcp coverage), `bun run coverage` gate green (per-package line/function thresholds), `bun run typecheck` clean, `bun run lint` clean.

## Kit-backed subsystems end to end

Notifications gains push (fcm/apns/webpush/huawei) and messaging (telegram/slack) channels over NotifyKit with per-channel provider config; email stays on `@framework/mail` by design. ## Generated application (`create`)

`bun run cli -- create apps/<name>` generates the complete application skeleton the release gate exercises: validated config (app/http/database/redis/queue/events), database + events providers, `audit_logs` in the canonical schema, `/health` + `/audit` + `/ws` (WebSocket event multiplexing) routes, `bin/server.ts` + `bin/worker.ts` + `bin/cli.ts` entry points, a health smoke suite, deployment compose, drizzle config, and a README. `make:crud --verify` then adds a full resource module. Generated apps are framework-workspace members: dependencies resolve through `workspace:*` after a root `bun install` (the `create` command runs it unless `--no-install`).

## Known limitations

- Generated CRUD supports a single primary key named `id` (uuid for new tables; uuid/integer/serial for existing tables). Unique/foreign-key fixtures, relations, enums and JSON columns are rejected rather than guessed.
- Generated resources support `--access public` and (after `make:auth`) `--access authenticated`; per-principal ownership is available as a service-level `ownedBy('userId')` scope but is not yet a `make:crud` flag, and the `?include=` relations DSL is not generated.
- Import/export covers CSV and JSON (streaming keyset batches, queued, partial-success imports). XLSX/PDF formats are planned. Export artifacts can live on any storage disk (`DiskExportStore`) or local disk (`LocalExportStore`).
- TOTP two-step login provisions the RFC 6238 §5 SHA-256 variant only (`algorithm=SHA256`); the weak-digest legacy variant is intentionally not offered, so authenticator apps without SHA-256 support (notably Google Authenticator) cannot enroll — modern apps (Aegis, 1Password, Bitwarden, FreeOTP, Ente Auth) work. Documented in `packages/auth/src/totp.ts`.
- TOTP secrets are stored in the `users` table unencrypted (standard practice — they must be retrievable to verify codes); database-at-rest encryption is a deployment concern.
- Node runtime is not selectable; only Bun is validated (the generated Dockerfile pins `oven/bun:1.4.2`). Promoting Node to a supported runtime still needs the ADR the enhancement plan called for.
- Batch bookkeeping (queue batches) lives in Redis with a TTL, so batch history is bounded by design; durable fan-out with history belongs in workflows.
- OpenTelemetry tracing/metrics and the "every CLI command has a status.md row" CI check are planned (M7 remainder). Per-status OpenAPI error schemas ship today: every declared error status gets an `ErrorEnvelope<status>` component whose `code` is the exact catalog enum (from `ERROR_CATALOG`, now shared via `@framework/core`), and `bun run coverage` enforces per-package line/function thresholds (measured baselines; template files and test files excluded).
- SMTP transport, the SMS notification channel, and validated s3/r2/minio storage against MinIO in compose are planned (M6 remainder).
- Migrations are forward-only by decision: `db:rollback` stays planned with a pointer to `db:fresh` (non-production) and authoring a new forward migration.
- The docs site vendors MDX 8's wasm32 runtime (`apps/docs/vendor/`, installed by a postinstall script) because bun skips wasm32 optional dependencies; `astro dev` renders through Node via the Cloudflare adapter's `prerenderEnvironment: 'node'`.
